# 教学页面自由选择章节设计

## 背景

`code-teacher` 曾把课程进度状态同时用作访问控制：已完成和当前章节可以读取，未开始章节在页面上被禁用，服务端也返回 403。AIoP 课程的全部 17 节内容已经生成，因此这种限制妨碍用户按兴趣、问题或工作需要跳转学习。

## 目标

- 用户可以从课程目录自由打开任何已生成的章节。
- `[x]`、`[>]`、`[ ]` 继续表达已理解、当前进度、未确认三种学习状态。
- 浏览其他章节不会自动修改教学进度，也不会被当作用户已理解该章节。
- 保留当前章节提示、返回当前章节、SSE 刷新、移动端和无障碍交互。
- 将自由浏览规则写入 `code-teacher` skill，后续生成的课程默认遵循相同行为。

## 非目标

- 不增加由浏览器写回课程进度的 API。
- 不记录用户最后浏览章节，不新增持久化字段。
- 不改变终端中的 `next` 确认流程和章节完成状态更新规则。
- 不重写 AIoP 已生成的章节正文。

## 方案

采用“自由浏览、进度独立”的单向只读模型：

1. 服务端仍根据大纲解析全部章节及其状态，但读取章节时不再拒绝 `pending` 状态。
2. 浏览器目录中的所有章节按钮均可点击；状态仅影响标记和颜色。
3. 当前浏览章节与课程当前进度分离。用户查看非当前章节时展示提示，并可一键返回当前章节。
4. `SKILL.md` 明确：浏览器可以展示所有已生成章节；只有终端中的明确确认才能推进学习进度。
5. `viewer-contract.md` 将“章节访问限制”替换为“所有已生成章节均可自由访问，进度状态不得作为访问控制”。

## 数据与交互

- `outline.md`：继续提供章节 ID、标题和进度状态。
- `state.json.current`：继续表示教学流程中的当前章节，不表示页面唯一可访问章节。
- `selectedId`：仅存在浏览器内存中，表示用户正在阅读的章节。
- `/api/chapters/:id`：只校验章节是否在大纲中、ID 是否安全、对应 Markdown 是否存在，不校验进度状态。

当 SSE 通知课程状态更新时：

- 用户正在查看当前章节：刷新当前章节。
- 用户正在查看其他章节：保留所选章节并显示“返回当前章节”提示。
- 所选章节从大纲中消失：回退到新的当前章节。

## 错误处理

- 非法章节 ID：400。
- 大纲中不存在的章节：404。
- 已列出但 Markdown 不存在：404。
- 课程状态不可读取：503。
- 不再因章节为 `[ ]` 返回 403。

## 测试

- 先增加服务端测试，证明 `[ ]` 章节能够返回 Markdown；修改前该测试应因 403 失败。
- 增加 viewer 静态契约测试，证明目录按钮不根据 `pending` 禁用，并为所有章节绑定选择行为。
- 更新 skill/contract 测试，证明文档明确区分“自由浏览”和“进度推进”。
- 运行 `node --test tests/teaching-server.test.mjs`。
- 对 AIoP 的 17 个章节重新运行 `validate-lesson.mjs`，确认 skill 修改未破坏已有课程。

## 风险与控制

- 用户可能误以为点击即完成：通过状态标记、当前章节提示和 skill 文案明确区分浏览与确认。
- 未来章节文件尚未生成：服务端保持 404，不展示空内容。
- 前后端规则不一致：服务端、viewer、契约文档和测试在同一变更中同步更新。
