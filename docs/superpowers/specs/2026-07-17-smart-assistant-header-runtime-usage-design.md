# 智能助手标题栏、运行时间与会话 Token 设计

## 目标

- 将聊天页标题“AI 助手”改为“智能助手”。
- 缩小标题栏高度、操作按钮、图标和间距，提高页面有效内容占比。
- 标题栏只展示当前会话的累计 token 消耗。
- 标题栏同时展示当前会话上下文占用与模型上下文上限。
- 当前会话有任务执行时，实时展示本次任务已经运行的时间。
- 刷新页面、切换会话或重新进入历史会话后，累计 token 仍保持准确。

## 非目标

- 不展示所有会话的总 token。
- 不把当前上下文窗口占用当成累计 token 消耗。
- 不新增 token 成本报表或按模型拆分统计。
- 不改变聊天区、会话列表或沙箱面板的信息架构。

## 界面设计

桌面端标题栏目标最小高度约 50px，横向内边距和元素间距同步收紧。标题字号保持清晰但略微减小。操作按钮高度从 36px 调整为约 30px，图标、文字间距和按钮左右内边距同步缩小。

标题改为“智能助手”。状态胶囊仅表达当前会话状态和累计 token：

- 空闲：`就绪 · 上下文 100/200K · 总消耗 65K`
- 执行中：`运行中 · 00:23 · 上下文 100/200K · 总消耗 65K`

运行时间仅在当前会话任务执行期间显示，每秒刷新；任务结束后恢复为“就绪”。移动端继续优先保证按钮可点击，不展示会导致拥挤的次要按钮文字。

上下文窗口占用与会话总消耗使用不同标签并列展示，避免把当前上下文大小误解为累计消耗。成本不在标题栏展示。

## 数据模型与接口

使用已有 `usage` 审计事件作为持久化事实来源，不新增数据库迁移。每次 agent 完成后已经写入包含 `inputTokens`、`outputTokens`、`cacheReadTokens` 和 `cacheCreationTokens` 的 usage 审计记录。

新增当前会话累计 token 查询接口。接口按租户和会话权限校验后，汇总该会话所有 `kind=usage`、`action=agent` 事件。累计 token 定义为 `inputTokens + outputTokens`；缓存 token 已包含在模型上报的输入 token 口径中，不重复相加。

响应至少包含：

```json
{
  "sessionId": "...",
  "totalTokens": 12345
}
```

## 运行时数据流

1. 进入或切换会话时，前端请求该会话的累计 token。
2. 当前会话开始任务时，前端记录该会话的运行开始时间。
3. 后端现有模型流会产生 `usage` 事件；前端接收后，把该事件的 `inputTokens + outputTokens` 加到当前会话的临时累计值中。
4. 多轮工具调用期间，每一轮模型 usage 到达后标题栏都会更新。
5. 任务结束、失败或终止后，前端重新请求服务端汇总值进行校准，并清除该会话运行计时。
6. 切换到其他会话时，标题栏只展示目标会话自己的累计 token 和运行状态。

前端按 session ID 保存累计 token、运行开始时间和活动状态，避免多个会话并行任务互相覆盖。

## 权限与错误处理

- 累计 token 接口复用会话访问校验，不能读取其他租户或无权访问的会话。
- 查询失败时不阻断聊天页；标题栏保留最近一次有效值，首次失败则显示 0。
- SSE usage 字段缺失或非法时忽略该事件，最终由任务结束后的服务端汇总校准。
- 连接中断、任务失败和用户终止都必须停止当前会话计时。

## 测试与验收

- 单元测试验证 usage 审计汇总只统计目标会话的 agent 用量，并且不重复计算缓存 token。
- HTTP 测试验证累计 token 接口、租户隔离和不存在会话时的行为。
- 前端测试验证标题文案、累计 token 请求、SSE usage 增量和运行时间状态。
- 构建并运行现有测试套件。
- 在桌面和移动宽度验证标题栏高度、按钮尺寸、文字截断、点击区域、无溢出和运行中动态展示。
- 开发完成后不提交 Git；部署到现有项目环境供用户查看。
